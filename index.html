Approach

How I take a problem to production.

Being forward deployed means working close to the problem and the people who have it. These four habits carry into everything I build.

  1. 01

    Embed and scope

    Start with the people who will use it. Map the real workflow, the data it touches, and the rules it must never break.

    In practice: Hopscotch’s return policy became the bot’s routing rules.
  2. 02

    Prototype on realistic data

    Get a working slice in front of stakeholders early, with scripted demo flows, so feedback is about behaviour, not slides.

    In practice: HealthGuard ships deterministic synthetic members and a stakeholder demo.
  3. 03

    Harden it

    Guardrails in code, not prompts. Cite sources, verify answers, gate releases on evals, trace every call, keep spend predictable.

    In practice: three-layer SQL safety, a RAGAS judge jury, spend guards.
  4. 04

    Hand it over

    Leave the team able to own it: tests and CI, architecture decision records, and a deployment design they can follow.

    In practice: ~250 tests in CI, ADRs, and an AWS deployment design.

01

HealthGuard

Agentic RAG for health-insurance members

healthguard-agent ↗

Answers members’ questions about plans, claims, prescriptions and prior authorizations. Every fact is cited, and the answer is verified before the member sees it.

  • Plans each question, then runs member-scoped SQL, pandas over a 5k-provider directory, and hybrid policy search in parallel.
  • SQL is safe in three layers: an AST guard, a read-only database role, and Postgres Row-Level Security.
  • A verify step checks groundedness and completeness, triggering a rewrite or a replan when an answer falls short.
  • Four cache layers, spend guards and per-turn cost tracking; a RAGAS judge jury and about 250 tests in CI.
  • LangGraph
  • FastAPI
  • Postgres + pgvector
  • Redis
  • RAGAS
  • OpenTelemetry
  • Docker
02

Learning Accelerator Agents

A multi-agent study coach

learning-accelerator-agents ↗

Give it a learning goal and it plans a curriculum, teaches from your own notes, quizzes and grades you, then adapts the plan to how you did.

  • LangGraph orchestration with human-in-the-loop plan approval and checkpointed sessions you can resume.
  • MCP for tools, A2A to run agents as network services, and a CrewAI agent called across frameworks.
  • A model per agent role through OpenRouter, with Langfuse tracing, token logging and DeepEval LLM-as-judge tests.
  • Extended from the freeCodeCamp multi-agent handbook code, with a production-readiness plan for on-prem deployment.
  • LangGraph

  • Langfuse
  • DeepEval
  • Streamlit
03

Hopscotch Support Bot

Customer support for a kids’ fashion retailer

hopscotch-s3-lcel-chatbot ↗

Reads each customer message, works out what kind of request it is and replies in the right style, or hands it to a person when the policy says it must.

  • One declarative LCEL pipeline: RunnableParallel gathers triage, safety, order-value and order-ID signals at once.
  • Escalations for child safety, skin reactions, orders over ₹5,000 and unclear cases are enforced in plain Python, not left to the model.
  • If triage can’t be parsed, the message goes to a human, never to a guess.
  • Built in stages: the raw OpenAI SDK, then LangChain, then LCEL.
  • LangChain LCEL
  • Streamlit
  • OpenRouter
  • pytest
